Earlyward is developed in the open. Earlyward detects and warns; it does not promise protection.

Documentation

This reference covers all diagnostic checks, filesystem and database write behaviours, network requests, and the privacy architecture of Earlyward.

Check List

Every check finding indicates what is wrong, the level of diagnostic confidence, the exact evidence discovered (such as file paths, line numbers, accounts, or response headers), and actionable remediation steps.

Runtime and outage

  • A1 The site answers but is broken

    Compared with a known-good baseline of the homepage, its own stylesheets, menu or REST routes have gone missing, or the homepage returns an error or an empty page.

  • A2 Code switched off after a crash, and fatal errors WordPress caught (recovery mode)

    Monitors whether WordPress entered recovery mode or paused extensions due to fatal PHP exceptions.

  • A3 Error logs that are huge, growing fast, or dominated by one repeating line

    Tracks diagnostic log files for explosive file growth or continuous repeating failure entries.

  • A4 WP-Cron that has stopped firing

    Detects overdue scheduled events indicating that WordPress background task processing has stalled.

Hosting

  • B1 Other WordPress sites readable by this site's PHP

    Flags when neighbor sites share the same Linux user account so one break-in reaches all of them.

  • B2 No open_basedir limit

    Warns when PHP can open files anywhere the hosting system account can access.

  • B4 wp-config.php that other accounts on the server can read or change

    Reports readable permissions as a note or writable permissions by other server accounts as a warning. Does not replace account-level isolation covered by B1.

  • B8 Plugin, theme or core updates are waiting

    Provides a note naming every pending update identified by WordPress.

  • D1 readme.html and license.txt that state the exact WordPress version are publicly served

    Low-confidence note pointing out public access to static version disclosure files.

  • D3 The home page is sent without standard security headers

    Checks for HSTS of at least six months, nosniff, clickjacking protection, referrer policy, and a content security policy. Uses a single header-only request to the site's own home page as a visitor receives it; note only, never sends an alert.

  • D2 None of the well-known login-protection or two-factor plugins is active

    Low-confidence note advising on login protection; does not inspect edge or hosting-level controls.

  • B7 WordPress has not managed to check for updates for days

    Reads timestamps WordPress already stored locally; makes no external network requests.

  • B5 PHP past end of life (or within 90 days of it), and a PHP memory limit under 64 MB

    Flags unsupported runtime versions and severely constrained memory thresholds.

  • B6 A disk that is nearly full

    Warns when remaining disk capacity is critically low in percentage and absolute bytes.

  • H4 Stale accounts

    Housekeeping info note reporting five or more subscriber or customer accounts registered over two years ago with no sign-in session and no recent shop activity. Reports counts only, never user names or email addresses, and never deletes accounts.

  • H3 Installed plugins that are not active

    Housekeeping info note highlighting inactive plugins that remain on disk.

  • H2 The newest backup in UpdraftPlus's own history is more than 14 days old

    Housekeeping info note reading the backup tool's existing history; never triggers an alert email.

  • H1 Older local UpdraftPlus backup copies that use space on the server

    Housekeeping note offering confirmed cleanup only when history proves the newest backup was sent to remote storage; never triggers an alert email.

  • B3 Backups, database dumps and config copies where the web server can serve them

    Checks for exposed database dumps or archives in web-accessible directories, querying loopback headers to verify if files are publicly served before raising severity to critical.

Malware indicators

  • C17 The uploads folder is not set to refuse PHP

    Inspects wp-content/uploads/.htaccess without uploading test files. Confirmed fix creates protective configuration on Apache or LiteSpeed; provides manual configuration rules for nginx.

  • C1 Hidden auto_prepend_file / auto_append_file loaders

    Scans .user.ini, php.ini, and .htaccess for stealthy file execution directives.

  • C2 Hex-named zip archives that malware uses to rebuild itself

    Detects hidden archive payloads commonly deployed in self-healing malware campaigns.

  • C3 Unexpected PHP: must-use plugins, drop-ins, hidden dot-files and loose PHP in wp-content

    Audits non-standard PHP files residing outside normal plugin and theme folders.

  • C4 Administrator accounts shaped like automation rather than people

    Identifies suspicious administrative accounts exhibiting machine-generated patterns.

  • C5 Application passwords on administrator accounts

    Flags persistent application passwords that survive administrative password resets.

  • C6 Custom CSS that hides a user from the Users screen

    Uncovers style rules injected to conceal malicious administrative accounts from the dashboard.

  • C9 Links hidden off-screen inside published content

    Detects SEO spam links disguised or positioned outside viewport boundaries in posts.

  • C15 PHP files in the web root that WordPress core does not ship, and renamed server-config or maintenance leftovers

    Detection only; identifies non-core PHP scripts and backup config files in the web root.

  • C16 Renamed plugin copies such as plugin.bak-20260809

    Finds dormant, unmanaged plugin clones that bypass WordPress update routines but remain accessible.

  • C13 Code that hides or runs other code in a theme's functions.php, header.php or footer.php

    Detection only; detects injected evaluation or obfuscation routines in active and inactive themes without editing theme files.

  • C12 PHP files inside the uploads folder

    Flags executable scripts in uploads (standard silence-is-golden placeholders are ignored; files with suspicious traits are critical).

Known vulnerabilities (opt-in)

  • E1 Plugins, themes or WordPress versions with a published vulnerability

    Matched locally on your server against the Wordfence Intelligence feed. Disabled unless EARLYWARD_WORDFENCE_KEY is explicitly defined in wp-config.php.

What it writes

Scans are read-only. Scanning never writes files or modifies database tables. Automatic writes occur solely to persist scan state, and file changes take place only when an administrator confirms a specific fix.

Automatic writes (no confirmation needed)

What Where Purpose Removed on uninstall
Scan results, alert state, baseline, and log measurements WordPress option earlyward_state (not autoloaded, capped at 500 findings) Stores findings, compares baseline, measures log changes, and emails only when alert findings change. Yes
Fix audit log WordPress option earlyward_fix_log (not autoloaded, last 50 entries) Records time, user, action, file, sha256 hash, and previous permissions when fixes run. Yes
Quarantine manifest WordPress option earlyward_quarantine (not autoloaded, max 200 items) Maintains records of quarantined files and folders so they can be restored. Yes (quarantined files remain)
Scan execution lock WordPress transient earlyward_scan_lock (10-minute expiry) Prevents overlapping scans from running at the same time. Yes
Scheduled scan job WP-Cron event earlyward_scan (hourly) Runs diagnostic scans in the background away from visitor traffic. Yes (also removed on deactivation)
Notification email Dispatched via wp_mail() to site admin Sent only when warning or critical findings change; info findings never send email. n/a

Viewing the admin page (Tools → Earlyward), Site Health tests, the admin bar badge, and the dashboard widget read existing stored results only; they write nothing and initiate no network requests.

Confirmed fixes (only after administrator confirmation)

Fixes appear under findings on the Findings tab. Each fix requires the manage_options capability, a valid nonce, and an explicit ticked confirmation box. Clicking a fix re-scans the target immediately to verify current state; actions are refused if conditions have changed.

Action Operation Reversibility
Restrict wp-config.php (B4) Applies chmod 600 if PHP owns the file. Immediately restored if PHP cannot read it. Reversible by applying original permissions from the fix log.
Delete exposed backup or dump (B3) Deletes the specific backup or dump file listed in the finding. Never deletes .php files. Not reversible from the admin UI. File hash is logged.
Delete maintenance leftover (C3) Deletes wp-content/maintenance.php if classified as a harmless generated remnant. Not reversible from the admin UI. File hash is logged.
Quarantine file (C15, C12, C13, D1) Moves file into locked directory wp-content/earlyward-quarantine-<random>/ renamed with a safe extension. Reversible using "Put back" on the Quarantine and fix log tab.
Quarantine plugin folder (C16, H3) Renames and moves selected plugin folders into the quarantine directory without running uninstaller scripts. Reversible using "Put back" on the Quarantine and fix log tab.
Update extensions and core (B8) Runs WordPress native upgrader for selected items, plugins and themes first, WordPress core last. Not reversible from UI; restore from a site backup.
Back up now Triggers an immediate background backup via UpdraftPlus if that plugin is active. Managed through UpdraftPlus.
Block PHP in uploads (C17) Creates wp-content/uploads/.htaccess blocking PHP script execution on Apache and LiteSpeed. Reversible by removing the file; original hash logged.
Delete older local backup copies (H1) Removes local backup archives older than the newest set, only when verified present on remote storage. Not reversible from UI. Local copies deleted; remote copy remains intact.
Delete for good (Quarantine tab) Permanently deletes an individual quarantined file or directory. Permanent; action and hash recorded in fix log.

Defining define( 'EARLYWARD_NO_FIXES', true ); in wp-config.php removes all fix buttons and disables all fix endpoints.

What it sends

Earlyward minimizes network activity and makes no external requests by default:

  • Local loopback requests only:
    • Check A1 sends two loopback requests (/ and /wp-json/ with cache-busting parameters) to test homepage availability and REST endpoints.
    • Check D3 sends one HTTP HEAD request (redirects not followed) to the site's own home page to read response headers.
    • Check B3 sends header-only HTTP HEAD requests (at most 8 per scan) to the site's own address to verify whether backup files found in the docroot are publicly accessible.
  • Wordfence Intelligence feed (E1, opt-in only):
    • Off by default. Active only if you define EARLYWARD_WORDFENCE_KEY in wp-config.php with a free API key.
    • When configured, downloads the public vulnerability feed at most every 12 hours (hourly after transient network errors).
    • The HTTP request sends only the API key. No site URL, no domain name, and no list of installed plugins or themes is transmitted.
    • Vulnerability matching is executed locally on your server. Results are stored in option earlyward_vuln_cache and deleted on uninstall.

Privacy statement

Earlyward is built with complete privacy in mind:

  • No analytics, tracking pixels, or telemetry beacons.
  • No phone-home calls or external license verification.
  • No external fonts, remote scripts, or third-party stylesheets.
  • No information regarding your site, plugins, users, or configuration ever leaves your server, except the local loopback checks and the optional vulnerability feed described above.
